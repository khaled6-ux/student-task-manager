# V1 multilingual interface

Branch `feat/v1-i18n` is based on `develop` at `fa45e7e` (merged landing page PR #3). No backend, database, environment-variable, OAuth configuration, dependency, or production changes are required.

## Behavior

English (`en`) is the default. Arabic (`ar`) uses full document RTL. Simplified Chinese (`zh-CN`) uses LTR. An accessible native language selector appears on the welcome page, the authenticated header, and the explicit development demo. The language names appear in their own languages.

The selection is saved under the nonsecret browser localStorage key `student-task-manager.locale`. It survives refreshes and account transitions, applies across routes, and synchronizes with other tabs. Unrecognized saved values default to English. If browser storage is blocked, the selection works for the current page, but cannot persist across a refresh. There is no account preference or additional API request. Language changes preserve loaded data, unsaved form values, mutation progress, visible errors, and calendar selection.

All authored interface copy is translated: landing, navigation, dashboard, profile, course/task editors and lists, categories, statuses, priorities, confirmations, loading and error states, accessibility labels, and calendar controls. API enum values and hash routes remain stable. Names, descriptions, course codes, timezone identifiers, and other user content are never sent through translation. Text inputs use automatic content direction. The landing illustration is translated sample copy; development demo records remain illustrative content as authored.

Document `lang`, `dir`, and title update before paint. Flex/grid direction places the Arabic sidebar on the right. Logical borders/spacing, mirrored directional arrows, start-aligned calendar/form controls, Arabic font fallbacks, wrapped controls, and stacked mobile statistics support narrow widths. Keyboard order stays aligned with the DOM. Reduced-motion preferences disable animation and smooth scrolling. Secondary workspace text was darkened after browser contrast testing.

## Dates and forms

`Intl.DateTimeFormat`, `Intl.NumberFormat`, and `Intl.PluralRules` provide locale-aware dates, day/month names, numbers, and all six Arabic task-count plural cases. Dates display in the profile's IANA timezone. Gregorian calendar arithmetic is retained for all languages; the existing calendar keeps Sunday as its first weekday. A calendar civil date is formatted in UTC after profile-timezone grouping to prevent a second browser-timezone shift.

The `datetime-local` editor now uses the **profile timezone** (UTC fallback), matching deadline display and calendar grouping. API timestamps remain ISO instants. DST gaps are rejected; newly entered ambiguous times choose the earlier occurrence, while unchanged stored deadlines retain their exact timestamps. Native picker presentation still follows browser/OS locale. See [profile-timezone deadlines](profile-timezone-deadlines.md).

## Translation architecture and maintenance

- `frontend/src/i18n/messages/{en,ar,zh-CN}.ts`: complete, centralized catalogs. Stable English source phrases serve as message keys (a gettext-style convention); API enums have explicit label entries. `taskCount.*` contains plural templates.
- `catalog.ts`: `MessageKey` union from the English catalog; every locale must implement the same typed keys. Parameter replacement inserts plain text, never HTML. Known application errors are localized at render time; unknown SDK/server messages use a safe translated generic error.
- `locales.ts`: locale metadata and storage key/validation.
- `useI18n.ts`: external-store subscription, persistence, cross-tab changes, document language/direction/title, and formatting helpers. It does not subscribe to auth or data APIs.
- `LanguageSelector.tsx`: shared native selector.
- `format.ts`: calendar civil-date and weekday formatting.
- `landing.en.ts`: landing structure and authored copy. The landing renderer translates only this authored structure; coverage tests ensure every nonnumeric/non-course-code string has a catalog entry.

Add a new key to English, Arabic, and Chinese together, including identical named placeholders when used. Use `t(key, values)` for authored copy. Keep error state in canonical message keys and translate at render time so an already visible error changes language. Keep user content outside `t()`. Do not translate internal routes, field names, enum values, or identity values. Tests enforce exact key coverage, target-language script presence, placeholder compatibility (Arabic one/two task forms omit the explicit count), and detect hardcoded JSX copy/accessible labels. For translation changes, native-speaker editorial review is recommended.



## Optional Chromium accessibility and responsive check

The reproducible `frontend/tests/browser/i18n-check.mjs` uses isolated contexts, synthetic sessions, and intercepted API fixtures only. **Start the frontend with the exact placeholder project below.** It blocks other outbound requests and never accesses real Supabase or application data.

```sh
# From frontend, terminal 1:
VITE_SUPABASE_URL=https://project.example VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_PREVIEW_PLACEHOLDER VITE_DEMO_MODE=false npm run dev -- --host 127.0.0.1 --port 5175 --strictPort

# From frontend, terminal 2 (optional tools outside the repository):
npm install --prefix /tmp/student-i18n-browser --cache /tmp/student-task-npm --no-save playwright@1.56.1 @axe-core/playwright@4.10.2
cp tests/browser/i18n-check.mjs /tmp/student-i18n-browser/i18n-check.mjs
node /tmp/student-i18n-browser/i18n-check.mjs
```

Requires system Chromium at `/usr/bin/chromium`, or set `CHROMIUM_PATH`. Optional `I18N_PREVIEW_URL` and `I18N_PREVIEW_DIR` override the local server URL and artifact directory (default `/tmp/student-i18n-previews`). Outputs stay outside Git.

The matrix covers three locales × four widths (1440, 820, 390, 320 px) × six pages/states (landing, dashboard, task editor, course editor, calendar, profile): 72 scenarios. It checks document language/direction, horizontal overflow, runtime errors, sidebar placement, no API requests from switching languages, landing keyboard/skip/section focus, reduced motion, and axe WCAG 2/2.1 A/AA violations. Screenshots are generated for landing/dashboard/task/calendar at desktop/mobile widths.

## Limits and manual review

Chromium automation and axe do not replace screen-reader, Firefox/Safari, mobile-device, or native-speaker review. Google-hosted OAuth pages and OS/browser date widgets choose their own language. Actual Google OAuth was not repeated in this task; automated tests cover the existing callback, session restoration, token refresh, sign-out and sign-in flows without contacting Google. No new live Supabase setup is needed.
